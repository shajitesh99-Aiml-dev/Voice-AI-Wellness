Executive Summary
An AI-powered emotional wellness app using an evolving room as its core metaphor combines gamification and ambient UI to maximise engagement. The concept: users check in daily, the AI extracts emotions, suggests a small mission (e.g. a 5‑minute walk), and the virtual room visually reflects the user’s mood and progress. This ties self-care to visible growth and ambience – akin to Finch’s pet-bird or Forest’s growing tree.
. The value is in reducing friction (the UI sells itself) and providing emotional resonance (Calm’s soothing visuals
). We prioritise polished interactivity over heavy algorithms, using off-the-shelf AI calls (OpenAI/Gemini) and simple rule-based logic.

Key points:

Concept & Differentiation: A “Behavioural Progression Room” that evolves (lighting, items, weather) as wellness improves – more personal and tangible than a chatbot. Finch’s success with a pet-bird metaphor
 and Forest’s tree-growth focus model
 show that visible growth taps into motivation.
Quick MVP Build: Use a React+Tailwind frontend for rapid UI, a FastAPI backend for simple endpoints
, and OpenAI/Gemini APIs for NLP. Store data in JSON/SQLite. Avoid complex infra: no auth, no mobile app, no custom ML.
Core Flows: Onboarding, daily check-in (text input), AI emotion extraction, mission suggestion, room-state update, streak counting, and insights/dashboard. Each flow has 1–3 screens or API calls (detailed below).
Tech Stack & Effort: Frontend in React (easy UI) + Tailwind (rapid styling); backend in FastAPI; AI via OpenAI’s GPT-4 or Google Gemini text APIs; charts with Recharts; simple animations with Lottie or CSS. Each feature is ~1–3h of work (difficulty ‘Easy’ to ‘Medium’).
Hackathon Plan (8–12h): Build UI skeleton and fake data flow first, then integrate AI calls and visuals, leaving time to polish UX and transitions. Key milestones: static UI, AI-driven logic, animations, polish (see timeline below). Fallbacks: if short on time, drop non‑essential bits (e.g. skip charts or Lottie).
Outcome: A demo-ready prototype where judges can type a mood, see AI‑generated mission, and watch the room transform accordingly. Success means a coherent, smooth experience that feels innovative and emotionally engaging (not “just another chatbot”).

Product Concept & Value Proposition
We propose “Your Emotional Ecosystem”: an ambient, gamified environment that visually mirrors your wellbeing. Instead of generic charts, the main screen is a room or living space whose lighting, clutter, decorations and even weather change with the user’s mood and habits. For example, late nights lead to a darker, messy room; consistent sleep brings a warm, sunlit scene; completing a mission might sprout a houseplant or add a cozy lamp. This creates immediate emotional resonance (users recognise “that’s how I feel”) and tangible progress (the room becomes nicer over time).

Gamification without Friction: Like Finch’s evolving pet bird (where self‑care becomes a “cozy daily ritual”)
 or Forest’s tree that grows during focused work
, our room rewards user effort with visual growth. This leverages intrinsic motivation and habit loops. The room is “the user’s mental space”, making the journey personal.
Ambient UI for Emotional Safety: Drawing from Calm’s design, we use soft colors and nature themes to evoke calm
. The interface is low-stress: the user’s first encounter might be a serene splash screen (“Take a deep breath”)
. This reduces anxiety around “being scored” and underscores support rather than correction.
AI Personalisation: The app remembers the user’s patterns. It “knows” if you’ve been stressed or inconsistent, then suggests missions accordingly. (For example, detecting late-night habits → mission to unwind earlier.) This adaptive loop makes it feel more intelligent than a static check‑in app. It directly addresses the biggest challenge in wellness apps: retention. By generating personalised missions and visuals, users want to return to see their room again.
Clear Demo Angle: In a hackathon demo, this product immediately feels useful: judges themselves can see and feel a difference as they interact. Contrast with a security dashboard demo: the judge is the user here. A shift from a gloomy to a brighter room is instantly understandable.
Positioning: Rather than “another AI chatbot”, this is a Behavioural Progression Engine for wellness. Most teams might build a mood-checking bot; we build an AI-driven narrative world. For instance, Finch “turns self-discipline into care” with a pet metaphor
. We apply that insight to an environment metaphor, which is less common and deeply memorable.

Below are the essential flows for a lean MVP. Each flow includes: UI screens/components, backend endpoint, data model, minimal logic/pseudocode, required tools, and an estimated build time + difficulty.

, and we mimic that tone (soft greetings, friendly icons).

2. Daily Check-In (Mood Reporting)
UI:
Chat-style input or quick-select mood indicators. Example: a text box with placeholder “How are you feeling today?” Or buttons: 😊 😟 😴.
Submit button (“Update”).
Endpoint: POST /api/checkin (send user ID + text or mood rating).
Data Model:
json
Copy
CheckIn {
  userId: int,
  date: date,
  rawText: string,      // user input or mood selection
  mood: number,         // e.g. 0–100 scale
  stress: number,       // 0–100
  energy: number,       // 0–100
  sleepQuality: number  // 0–100
}
Logic / Pseudocode:
python
Copy
def handle_checkin(userId, rawText):
    # Call LLM to extract sentiment metrics
    prompt = f"Extract mood, stress, energy from: \"{rawText}\""
    response = llm_api.call(prompt)
    scores = parse_response(response)  # e.g. {mood:75, stress:30, energy:50}
    checkin = CheckIn(userId, date.today(), rawText, **scores)
    save_to_db(checkin)
    return { updatedScores: scores }
Tools/Libraries: OpenAI or Gemini API for NLP; React for input UI (use useState), fetch API for request.
Effort: ~2h (Easy) – hooking up text input and a single API call.
Notes: This step powers everything. We use an LLM prompt like “Identify the user’s emotional state from this message”. (Sample prompts later.) We must handle only basic metrics; avoid complex therapy. The UI stays calm (avoid any negative feedback).
3. Mission Generation
UI:
Immediately after check-in, show a “Today’s Mission” card: e.g. “Mission: Take a 5-minute walk after lunch three times this week.” with a checkbox to mark completion.
Endpoint: Could be part of check-in response, or a separate POST /api/mission that uses recent check-in data.
Data Model:
json
Copy
Mission {
  id: int,
  userId: int,
  text: string,
  dateAssigned: date,
  completed: bool
}
Logic / Pseudocode:
python
Copy
def generate_mission(userId):
    pattern = analyze_recent_checkins(userId)  # e.g. detect high stress at night
    if pattern == "late_night":
        mission = "No screens after 11 PM for 3 days"
    elif pattern == "low_exercise":
        mission = "Do a 5-minute walk after lunch for 3 days"
    else:
        mission = "Take 3 deep breaths twice a day"
    save_to_db(Mission(userId=userId, text=mission, completed=False))
    return mission
Alternatively, use LLM to refine:
python
Copy
prompt = f"Suggest a small actionable self-care mission for a user who reports [pattern]."
mission = llm_api.call(prompt)
Tools/Libraries: OpenAI/GPT or a simple rule engine; React to display the mission; a basic checkbox or button (no backend, or POST /api/mission/complete).
Effort: ~1–2h (Easy) – simple conditionals or prompt.
Notes: Keep missions very short and positive (avoid directives like “must”, keep tone gentle). They should feel doable. For hackathon speed, we can hardcode a few templates and fill keywords, instead of trusting the AI to invent something too long.

Tools, Libraries and Estimations
Frontend: React (component-based UI) + Tailwind CSS (rapid styling)
. Use Create React App or Vite for speed.
Backend: FastAPI (Python) – modern, async-ready, quick to set up. Hackathon tip: FastAPI has auto-doc and simple endpoints, similar to Flask
.
AI/NLP: OpenAI GPT-4 or Google Gemini (via their API). Use their Python or REST APIs. For example, Google’s GenAI SDK shows calling client.models.generate_content(model="gemini-3-flash-preview", contents="...") to get text
.
Storage: SQLite or JSON files. (No need for a full DB; just a few tables.)
Animations:

PNG State Swaps: Easiest – pre-draw 3-4 room images (e.g. “messy”, “neutral”, “cozy”) and swap them. (0 coding, just img src changes.)
Lottie: For more dynamism (e.g. gently swaying curtains), use Lottie JSON. Lottie yields high-quality vectors; JSON is smaller than PNGs
 but requires some design/AE prep.
CSS/Canvas: Moderate effort – e.g. CSS filters for color shift, or a <div> with animated background. Canvas animations with libraries (p5.js) possible but probably overkill.
Charts: Recharts (React+D3 charts). Very easy to plug in with npm install recharts.
Deployment: Vercel or Netlify for frontend; Render or Heroku for FastAPI. Even simpler: run backend locally (but Vercel can run Python now, or use Vercel AI SDK as in Gemini docs).

Prompts and AI Guidelines
Mood/Emotion Extraction Prompt
Role & tone: Empathetic, structured output.

vbnet
Copy
System: You are an AI assistant that analyzes a user's short journal entry for mood and stress. 
User: "<user text>" 
Assistant: 
Prompt: “Read the user’s statement and extract their mood (0–100 calm/happy), stress level (0–100), energy (0–100), and any notable keywords. Respond in JSON: {“mood”:…, “stress”:…, “energy”:…, “keywords”: […]}.”

Use few-shot examples if needed.
Safety: Don’t give medical labels (no “You have depression”). Just descriptive tone. Focus: “The user seems low energy and anxious”.
Example Template:
css
Copy
User: "I had a terrible day at work and I'm exhausted." 
Assistant: { "mood": 30, "stress": 90, "energy": 20, "keywords": ["terrible day", "exhausted"] }
Mission Generation Prompt
Goal: Suggest one actionable wellness mission matching user’s needs. Tone encouraging but not bossy.

sql
Copy
System: You are a supportive wellness coach. The user’s recent check-ins show [pattern, e.g. "high evening stress, low energy"]. 
Assistant: 
Prompt: “Suggest one simple, positive habit or mission for this user. For example, 'Take a 5-minute walk after lunch today.' Keep it brief and achievable.”

Encourage: Use “You might try” not commands.
Safety: No medical claims. If pattern is severe (e.g. mentions self-harm), the system should not pretend to fix it; ideally fallback: “It sounds hard. Consider talking to a professional or a friend.”
Example: If pattern = “low sleep quality”: “It sounds like you’ve been tired. Mission: Set an alarm to start winding down (screens off) at 9 PM for the next 3 nights.”
These prompts should include a system message directing tone (encouraging, non-judgemental) and guard against giving risk advice. Referencing OpenAI’s safety guidelines, we avoid diagnosing or only say “if you feel overwhelmed, consider contacting support” as needed
.
